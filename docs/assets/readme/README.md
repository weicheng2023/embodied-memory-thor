# README visual assets

These assets are research-facing summaries, not additional experimental rows.
They are generated from repository code and frozen evidence rather than edited
by hand.

| Asset | Source and role |
| --- | --- |
| `system_overview.svg` | Deterministic architecture diagram generated by `scripts/render_readme_assets.py`; it encodes the planner/evaluator information boundary documented in `docs/architecture.md`. |
| `memory_horizon_retention.svg` | Deterministic chart generated from the accepted Phase-7B descriptive result JSON. |
| `book_reacquisition.gif` | Presentation-only replay generated from one successful real AI2-THOR Phase-7A configuration. It combines saved in-memory RGB frames with planner-visible trace fields. |
| `book_reacquisition_poster.png` | Static first frame of the same replay, suitable for clients that do not animate GIFs. |
| `demo_manifest.json` | Machine-readable role, source boundary, provenance hashes, and hidden-state declarations for the replay. |

The replay is deliberately **not formal comparative evidence**. It is a visual
explanation of what one episode means. It does not use a desktop screenshot,
and its overlay excludes evaluator-only state, object identifiers, hidden
coordinates, and reachable-graph data.

Regenerate the two public-data diagrams from any development environment:

```bash
python scripts/render_readme_assets.py
```

Regenerating the GIF first requires the verified AI2-THOR runtime and the local
evaluator-only Phase-7 registry described in
`configs/evaluator_only/README.md`:

```bash
python scripts/run_readme_demo.py
python scripts/render_readme_assets.py \
  --trace-dir outputs/readme_presentation_source
```

The source trace remains ignored because it belongs to the same
planner/evaluator privacy boundary as other real-episode artifacts. The public
manifest records content hashes without publishing hidden setup data.
